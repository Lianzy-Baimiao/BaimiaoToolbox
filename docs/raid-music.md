# 嗜血音乐：大秘境检测与无声诊断（1.9.8）

## 1.9.13 音频资源调整

插件不再附带私人音乐文件，也不再注册原内置曲目。默认选项改为未配置的自定义路径；旧内置选项只迁移为自定义，保留已填路径、声道和循环设置。请在“音乐与试听”选择其他共享声音，或在“循环与自定义”填入自己的路径 / fileDataID 后试听。新包不含该音频，旧历史和旧包未清理。

此调整不改变下面的嗜血触发、倒计时与出本清理规则。

## 1.9.8 修复了什么

旧实现以显示文字“嗜血中”触发播放。若大秘境里嗜血增益查询返回空值、疲惫仍公开可读，代码只显示“冷却”，从未调用 PlaySoundFile，因此可以**没有报错，也完全没有音乐**。

离线测试已用实际模块与上述模拟返回值复现旧问题并验证修复；这不是本次用户副本的现场数据，不能据此断言其无声必然只有这一个原因。隐藏团队监控也会抑制音乐的旧缺陷一并修复，但不将它当成用户大秘境无声的原因。

用户已确认 1.9.7 在大秘境能响。1.9.8 另修复出本后推定倒计时未结束：旧逻辑没有副本边界，过图后晚加载的旧疲惫也可能制造新触发。已用实际模块复现这两条路径；本次出本修复仍待现场确认。

## 当前规则与边界

- 公开可见的本人嗜血增益优先；结束时间公开时显示实际剩余时间，时间不可读时只显示“嗜血中”。不读取秘密时间作比较、算术或格式化。
- 增益读不到时，仅在小队/团队副本内、本人疲惫经历**确认没有 → 新出现**时，推定开始约 40 秒嗜血；文字明确带“约”，不冒充游戏真实计时。
- 登录、进入世界、模块重新启用时先建立基线，已有疲惫不当作新施放；API 报错或秘密结果打断基线，不凭“未知 → 存在”触发。疲惫时长和结束时间均公开时，仅接受应用时间距今约 2 秒内的新出现，不用晚加载的旧疲惫开启新窗口。
- 出本立即清除备用窗口，过图暂停，区域变化与轮询都检查边界；野外没有真实可读嗜血增益就不会显示“嗜血中”。疲惫仍在时显示“冷却”，不表示仍有嗜血效果。
- 仅采样玩家本人，忽略队友光环事件。隐藏监控行、隐藏小队/团队场景不会关闭音乐；模块开关和音乐开关仍有效。
- 推定窗口到期、疲惫移除、玩家死亡或模块关闭会停止循环；同一轮直接检测与备用检测不重复起播。
- 主动点击“停止”/“试听”取消自动循环，不在下一次轮询抢回；下次嗜血或重新开关音乐后恢复自动触发。
- 备用判定不是对真实增益的完整观测：如果疲惫本身也不可读、没有可靠的新获得边沿，或该变体没有已收录的疲惫，仍可能漏播。真实时长与 40 秒不同、只取消增益但疲惫仍在时，备用窗口也可能与真实效果不一致。不绕过游戏限制。
- 不依赖 EUI，不自动更换音乐/声道，不改动 WTF 或其它插件。

## 不响时怎么查

1. 覆盖 1.9.8 后在游戏内 `/reload`。在设置中确认嗜血音乐已启用，先“试听”所选声音。
2. 下一把大秘境开嗜血后，如果还是无声，**先不要重载**，输入 `/raidcd music` 并保留输出。
3. 对照两段核心信息：
   - **上次触发：未检测到**：这一登录会话还没有检测到嗜血；其它触发会附距今秒数，避免把很早的成功当成本次。
   - **声音资源未找到**：检查共享媒体插件是否已加载；自定义模式检查路径/fileDataID。
   - **客户端拒绝播放 / 播放接口调用失败**：检测可能已经成功，但声音请求没有成功。
   - **客户端已接受请求**：不代表一定听得见。检查总开关、总音量、所选声道开关/音量；可手动切换主声道后试听作对比，不要仅依据“音乐”开关判断 SFX 声道。
4. 命令还会显示模块/自动开关、当前状态、所选声音和资源解析结果。结果仅保存在本次登录内存中，试听不会覆盖最近一次自动请求结果；无自动聊天刷屏。

```powershell

python -X utf8 -m unittest discover -s tests -p test_followup_198.py -q
python -X utf8 -m unittest discover -s tests -q
```
